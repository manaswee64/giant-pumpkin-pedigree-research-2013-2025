# Pedigree, Performance and Geographic Trends in Giant Pumpkin Competitions, 2013–2025

Code and data for a study of **23,000+ competition records** of *Cucurbita maxima* (Atlantic giant pumpkin), examining how documented pedigree structure, record weights and geographic representation changed between 2013 and 2025.

The central findings reported in the manuscript:

- Annual maximum weight rose by approximately **53 lb per year** across the study period.
- There is **no robust evidence** of a consistent slowing in that trend.
- There is **no robust evidence** of increasing concentration in documented parental lines, once unequal yearly sample sizes are accounted for by rarefaction.

Every number and figure in the manuscript is generated by the scripts in this repository. Nothing is calculated by hand.

## Data

`data.csv` — one row per competition entry, with the columns:

| Column | Meaning |
|---|---|
| `Year` | Competition year (2013–2026) |
| `Place` | Finishing place, or `EXH` for exhibition entries |
| `Weight_lbs` / `Weight_kg` | Recorded fruit weight |
| `Grower_Name` | Grower as recorded by the weigh-off |
| `City`, `State_Province`, `Country` | Grower location |
| `GPC_Site` | Weigh-off event name |
| `Seed_Mother`, `Pollinator_Father` | Documented parents |
| `OTT`, `Estimated_Weight`, `Pct_Chart` | Circumference/estimation fields, where reported |

## How to run

Every script reads `data.csv` from the working directory and writes its own output folder. All are seeded (`RANDOM_SEED = 42`) and should reproduce identical results.

```bash
python mega_analysis.py            # -> mega_analysis_output/
python phase3_rarefaction.py       # -> phase3_rarefaction/    (rarefied pedigree diversity)
python phase3c_pedigree_network.py # -> phase3c_output/, phase3c_network/
python phase4_record_trajectory.py # -> phase4_output/         (record-weight trend)
python phase5_geography.py         # -> phase5_output/         (geographic expansion)
python phase6_statistical_analysis.py  # -> phase6_output/     (models, diagnostics)
python phase7_figures.py           # -> phase7_figures/        (publication figures; needs phase6_output/)
python phase_rq1_final.py          # -> rq1_final_output/      (pedigree diversity + network)
```

`phase7_figures.py` **must run after** `phase6_statistical_analysis.py`, because it reads `phase6_output/`. Each script's docstring lists its exact inputs and outputs; run any script standalone with `python <script>.py` from the repo root.

`explore.py` is exploratory only and does not produce anything used in the manuscript.

## Method notes

**Rarefaction (`phase3_rarefaction.py`).** Pedigree coverage is not constant across years: early
seasons have far fewer named-parent records than later ones, and raw diversity metrics are
sensitive to sample size. Each year is therefore subsampled 1,000 times to the largest sample size
common to *all* years, and metrics are averaged over those subsamples. This is the direct control
for the coverage-over-time confound; results should be read from the rarefied files, not the raw
ones.

**Parent classification.** `Seed_Mother` and `Pollinator_Father` entries are classified as `named`,
`self`, `open`, `unknown` or `missing`. Only `named` entries enter the diversity calculations.
Placeholder strings ("self", "open pollinated", "unknown", "n/a", "sib", etc.) are enumerated
explicitly in each script.

**Multiple comparisons.** Where many yearly correlations are tested, `phase_rq1_final.py` applies
Benjamini–Hochberg correction (`statsmodels.stats.multitest.multipletests`).

## Known limitations

1. **Confounding of the weight trend.** The 53 lb/year trend cannot, on this dataset alone, be
   cleanly separated from concurrent changes in growing technique, fertiliser and irrigation
   practice, entrance numbers, and weigh-off calibration standards. The trend is real in the
   records; its *cause* is not identified by these analyses.
2. **Missing values coded as `0`.** Some rows report `OTT`, `Estimated_Weight` and `Pct_Chart` as
   `0`, which in context appears to mean "not measured" rather than a true zero. These columns are
   not used in the primary analyses; any future analysis must treat `0` as missing.
3. **Manual curation.** Grower names, city and event names come from varied national sources and
   contain inconsistent spellings and duplicated entities. Automatic canonicalisation is
   case-and-whitespace only; no fuzzy matching is applied.
4. **Coverage bias.** Records are unevenly distributed across countries and events. Geographic
   trends describe *representation in the recorded dataset*, not the true population of growers.
